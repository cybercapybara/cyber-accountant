# Дизайн-система cyber-accountant (frontend)

Кабинет бухгалтера ТОО в Казахстане. Пользователи — владелец бизнеса и
бухгалтер. Интерфейс — **только на русском**, без i18n-библиотеки: строки
живут прямо в JSX. Термины — казахстанские бухгалтерские (см. §6).

Это не новая тема оформления, а опись того, что уже есть в
`tailwind.config.js` / `src/index.css` / `src/components/ui/*`, плюс
маленький набор общих примитивов поверх них. Не изобретать токены заново —
переиспользовать.

## 1. Токены (уже существуют — просто используем)

Все цвета — `hsl(var(--token))`, объявлены в `src/index.css` для `:root`
(светлая тема) и `.dark` (тёмная). Тема переключается классом `.dark` на
`<html>` (см. `Nav.tsx`, `toggleTheme`) и запоминается в
`localStorage['theme']`.

| Токен                            | Назначение                           |
| -------------------------------- | ------------------------------------ |
| `background` / `foreground`      | фон страницы / основной текст        |
| `card` / `card-foreground`       | поверхность карточек                 |
| `primary` / `primary-foreground` | акцент (индиго), кнопки по умолчанию |
| `secondary`, `accent`, `muted`   | второстепенные поверхности и текст   |
| `destructive`                    | опасные действия, ошибки             |
| `border`, `input`, `ring`        | границы, поля ввода, фокус-кольцо    |

Не хардкодить hex/rgb в новом коде — только классы Tailwind, завязанные на
эти переменные (`bg-card`, `text-muted-foreground`, `border-border`, …).
Исключение — тонально-контрастные статус-бейджи (см. §5): они используют
именованные оттенки Tailwind (`amber-500`, `emerald-500`, …), потому что
семантика статуса (черновик/проведено/ошибка) не входит в 6 токенов темы.
Каждый такой оттенок задан для обеих тем через `dark:` — не добавлять новый
без пары свет/тьма.

Радиус — `--radius` (0.375rem), уже подключён к `rounded-{sm,md,lg}`.

## 2. Типографика

- Заголовок страницы (`PageHeader`, см. §4): `text-3xl font-bold`.
- Заголовок карточки (`CardTitle`): `text-lg font-semibold`.
- Подзаголовок/описание: `text-sm text-muted-foreground`.
- Тело/таблицы: `text-sm` (14px) — это и есть плотность приложения, крупнее
  не нужно.
- Моноширинный текст (`font-mono`) — только для денег, идентификаторов
  (БИН/ИИН, ID, хэши) и кодов счетов.

## 3. Сетка и адаптивность

- Контейнер страницы: `container mx-auto max-w-{2xl..6xl} py-8 space-y-6`
  (ширина подбирается под контент: формы — `max-w-md`/`max-w-2xl`, таблицы —
  `max-w-4xl`/`max-w-6xl`).
- Формы — **одна колонка на мобильном**, `sm:grid-cols-2`/`sm:grid-cols-3`
  на десктопе (`grid grid-cols-1 sm:grid-cols-2 gap-3`) — уже так во всех
  формах, сохраняем паттерн.
- Таблицы — оборачивать в `<div className="overflow-x-auto">` (уже
  сделано почти везде через `CardContent className="overflow-x-auto"`),
  чтобы на узком экране таблица скроллилась горизонтально, а не ломала
  вёрстку страницы.
- Карточки-ярлыки (дашборд, admin/Dashboard) — `grid sm:grid-cols-2
lg:grid-cols-3`.

## 4. Общие примитивы (`src/components/`)

Маленькие, типизированные, без новых зависимостей — поверх существующих
`ui/*`. Импортировать вместо копирования разметки по месту.

### `PageHeader`

Заголовок + описание + действия справа (перетекает на мобильном).

```tsx
<PageHeader
  title="Контрагенты"
  description="Поставщики, покупатели и другие стороны сделок вашей организации."
  actions={<Button onClick={...}>Новый контрагент</Button>}
/>
```

### `EmptyState`

Единый пустой экран (таблица без строк, ещё не готовый раздел). Иконка —
`lucide-react`.

```tsx
<EmptyState
  icon={Inbox}
  title="Контрагентов пока нет"
  description="Добавьте первого контрагента, чтобы выставлять счета и акты."
  action={<Button onClick={...}>Новый контрагент</Button>}
/>
```

### `ErrorState`

Единый экран ошибки загрузки, с опциональной кнопкой повтора.

```tsx
<ErrorState
  message={apiErrorMessage(error, 'Не удалось загрузить данные.')}
  onRetry={() => refetch()}
/>
```

### `StatusBadge`

Одна визуальная семья бейджей для любого статуса (draft/posted/reversed,
final/sent/…, pending/processing/completed/failed/dead и т.д.). Компонент
не знает словарь статусов — каждая страница передаёт `label` (уже
переведённый) и `tone` (семантика цвета, см. §5).

```tsx
<StatusBadge label="Проведено" tone="success" />
```

### `Money`

Деньги — **всегда** моноширинным шрифтом, табличными цифрами и (в ячейке
таблицы) по правому краю. Формат: `12 345,67 ₸` — пробел между разрядами
тысяч, запятая — десятичный разделитель, знак тенге через пробел в конце
(см. §7). Принимает **целое число тиын** (см. `lib/money.ts`) — никогда
`number`-тенге или уже отформатированную строку.

```tsx
<Money tiyn={toTiyn(line.amount)} />
// в колонке таблицы:
{ header: 'Сумма', className: 'text-right', cell: (row) => <Money tiyn={row.amountTiyn} /> }
```

Опция `hideCurrency` — когда сумма стоит рядом с явным «₸» в тексте, чтобы
не дублировать символ.

### `LoadingTable`

Скелетон таблицы на время первой загрузки — самостоятельный `<table>` с
`Skeleton`-строками. `DataTable` использует его внутри себя, но составные
экраны (детальная карточка, ещё не обёрнутая в `DataTable`) могут
подключить его напрямую.

```tsx
<LoadingTable columns={4} rows={5} />
```

Все пять примитивов уже подключены в `src/components/DataTable.tsx`
(единая обвязка `isLoading` → `LoadingTable`, `error` → `ErrorState`,
пусто → `EmptyState`) — это автоматически причёсывает состояния везде, где
уже используется `DataTable` (Counterparties, Journal, Documents,
Organizations, admin/\*).

## 5. Статус-бейджи — семантика цвета

`tone` — это _значение_, а не цвет: одна и та же семантика («что-то ждёт»,
«всё хорошо», «что-то пошло не так») выглядит одинаково для проводок,
документов и фоновых задач. Оттенки заданы с парой light/dark (см. §1).

| tone      | Смысл                              | Примеры статусов                                   |
| --------- | ---------------------------------- | -------------------------------------------------- |
| `neutral` | нейтрально/архивно                 | `reversed` (сторно), `inbox`, `archived`           |
| `warning` | черновик/ожидание/требует внимания | `draft`, `pending`, `queued`                       |
| `info`    | в процессе/распознано              | `processing`, `recognized`, `linked`, `sent`       |
| `success` | успешно завершено                  | `posted` (проведено), `final` (готов), `completed` |
| `danger`  | ошибка/просрочено                  | `failed`, `dead` (DLQ)                             |

Пример словаря на странице (переводит код статуса в `{label, tone}`, сама
страница знает свою доменную область):

```tsx
const JOURNAL_STATUS: Record<JournalEntry['status'], { label: string; tone: BadgeTone }> = {
  draft: { label: 'Черновик', tone: 'warning' },
  posted: { label: 'Проведено', tone: 'success' },
  reversed: { label: 'Сторно', tone: 'neutral' },
};
```

## 7. Деньги — формат и вёрстка

- Источник истины — `src/lib/money.ts`: сумма всегда хранится и передаётся
  как **целое число тиын** (1/100 тенге), никогда как `number` тенге
  (плавающая арифметика на деньгах запрещена).
- `formatTiynRu(tiyn)` → `"12 345,67"` (пробел-разрядность, запятая).
  `Money` добавляет к этому суффикс `₸`.
- Правило вёрстки: любая денежная колонка в таблице —
  `className: 'text-right'` на `Column`; сама сумма — `font-mono
tabular-nums`, это уже внутри `Money`.
- Строка «Итого»/сводка — тот же компонент `Money`, просто крупнее
  (`text-base` снаружи), а не отдельный формат.

## 8. Иконки

`lucide-react` (уже в зависимостях, ничего нового не добавляем).
Размер по умолчанию в таблицах/кнопках — `h-4 w-4`, в шапках
карточек-ярлыков — `h-6 w-6`. Декоративные иконки — `aria-hidden="true"`;
если иконка — единственный контент кликабельного элемента, у элемента
обязателен `aria-label`.

## 9. Состояния — контракт

Каждый экран со списком/данными обязан пройти по одному и тому же дереву
состояний (это и есть чинимый диагноз «каждая страница изобретает своё»):

1. **Загрузка** (первая, без данных) → `LoadingTable` / скелетон.
2. **Ошибка** → `ErrorState` с сообщением из `apiErrorMessage(error, '…')`
   и, где есть `refetch`, кнопкой «Повторить».
3. **Пусто** (запрос успешен, данных 0) → `EmptyState` с понятным текстом
   и, где уместно, действием («Новый контрагент» и т.п.).
4. **Нет прав** — страница просто не должна быть в этом состоянии видна
   (гейт на уровне `routes/manifest.tsx` / `ProtectedRoute`); там, где
   часть контента внутри страницы условна по роли (например, управление
   участниками только для владельца/админа), скрывать блок, а не
   показывать заблокированную кнопку без объяснения.

## 10. Доступность

- У каждого интерактивного элемента — видимое доступное имя или
  `aria-label` (иконка-кнопка без текста обязана иметь `aria-label`).
- Фокус-стили не убираются нигде: `focus-visible:ring-2
focus-visible:ring-ring` — стандартный паттерн уже во всех интерактивных
  элементах, сохраняем его в новом коде.
- Модалки/диалоги (`Modal`, `ConfirmDialog`) уже фокус-трапят и возвращают
  фокус — переиспользовать их, не писать новый попап вручную.
- `role="alert"` / `aria-live` — на сообщениях об ошибке валидации и
  тостах (уже так в `FormField`, `toaster.tsx`).
