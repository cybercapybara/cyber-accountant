# Конструктор шаблонов документов — план реализации

**Спека:** [2026-08-17-template-constructor-design.md](../specs/2026-08-17-template-constructor-design.md)

**Цель:** организация заводит собственные шаблоны из блоков, форма ввода строится по шаблону, готовые переменные подставляет сервер.

**Порядок задач выбран так, чтобы польза приходила раньше редактора.** Задача 1
чинит существующую боль (перенабор своих же банковских реквизитов в каждом
счёте) и не требует ни одного блока. Если фаза остановится после неё, продукт
всё равно станет лучше.

## Глобальные ограничения

- Целочисленные тиыны (`long long`) для любых денег; строки печатает сервер.
- Права — deny-by-default через `API_REQUIRE_ORG_PERM`; новые ресурсы
  объявляются в матрице явно.
- Все запросы org-scoped; `org_id` — обязательный параметр репозитория.
- Сборка и тесты — только в GitHub Actions.
- Заголовочные файлы в `src/` (ADR 0003).
- Миграции forward-only, применяются init-контейнером при раскатке.

### Задача 1: Реквизиты организации и расчётные счета

**Почему первой:** сегодня `definitions.party` в схемах заполняет клиент
целиком, а в `organizations` нет ни адреса, ни директора, ни счетов. Пока их
нет, переменные `org.*` из §7 подставлять неоткуда.

**Файлы:**
- Создать: `migrations/025_org_requisites.sql`
- Создать: `src/repositories/BankAccountRepository.hpp`
- Изменить: `src/api/OrganizationsController.hpp`
- Тест: `tests/integration/test_org_requisites.cpp`

**Содержание:**
- `ALTER TABLE organizations`: `legal_address TEXT`, `director_name TEXT`,
  `director_position TEXT DEFAULT 'Директор'`.
- `CREATE TABLE bank_accounts`: `id`, `org_id` FK, `iik`, `bank_name`, `bik`,
  `kbe`, `currency` (default `KZT`), `is_primary BOOLEAN`, `created_at`.
- Частичный уникальный индекс: не более одного `is_primary` на организацию.
- CRUD под правом `Resource::kMembers`-уровня (реквизиты правит владелец).

### Задача 2: Подстановка реквизитов организации в первичку

**Файлы:** `src/docgen/InputPolicy.hpp`, `src/api/DocgenController.hpp`,
тест `tests/integration/test_documents_api.cpp`

Сервер заполняет `seller` из реквизитов организации, как уже делает с суммами.
Присланный клиентом `seller` — 422 `not_allowed_override`, тем же механизмом,
что и `total_words`. Так два документа одной организации перестают расходиться
в реквизитах **по построению**, а не по внимательности бухгалтера.

### Задача 3: Хранилище шаблонов

**Файлы:** `migrations/026_document_templates.sql`,
`src/repositories/TemplateRepository.hpp`, тест на изоляцию арендаторов.

Таблица по §5 спеки. Опубликованная версия неизменяема (триггер, как у
`journal_entries`). Архивация вместо удаления: на версию шаблона ссылаются
выпущенные документы.

---

### Задача 4: Разрешение шаблона из БД при рендере

**Файлы:** `src/docgen/TemplateRegistry.hpp`, `src/docgen/RenderJob.hpp`,
тест `tests/integration/test_render_job.cpp`

Порядок: шаблон организации → шаблон площадки → диск. `source` материализуется
в тот же `mkdtemp`-каталог как `main.typ`; песочница, `--root` и `timeout 60`
не меняются. Тест обязан доказать, что шаблон одной организации недостижим из
другой и что `read` за пределы корня невозможен.

---

### Задача 5: Каталог переменных

**Файлы:** `src/docgen/Variables.hpp`, `src/api/DocgenController.hpp`, тесты.

Типизированный каталог по §7.3. Ставка НДС берётся из `tax_rates` **на дату
документа**, а не константой: ставки — данные, не код (§7.1 главной спеки).

---

### Задача 6: Блоки → Typst

**Файлы:** `src/docgen/BlockCompiler.hpp`, тесты на каждый тип блока.

Порождает исходник при публикации, не при рендере. Обязан переносить идиомы,
выстраданные при миграции: `overhang: false`, `hyphenate: false` для длинной
прозы, `box` для токенов со слешем, `sigrule` вместо голой линии.

---

### Задача 7: Схема и форма из блоков

**Файлы:** `src/docgen/FormBuilder.hpp`, тесты.

Из блоков порождаются `schema` (контракт валидации) и `form` (подписи рус./каз.,
порядок, группы, виджеты). Производные поля в форму не попадают.

---

### Задача 8: Гейт при публикации

**Файлы:** `src/docgen/PublishGate.hpp`, `scripts/check-render.py` (вынести
проверки в импортируемый вид), тесты.

Порождает фикстуру и `expected.txt`, прогоняет четыре слоя, отклоняет
публикацию с указанием потерянного. Тест обязан включать намеренную поломку —
гейт, который никогда не кусался, не доказан.

---

### Задача 9: API шаблонов и права

**Файлы:** `src/api/TemplatesController.hpp`, `src/tenancy/OrgPermissions.hpp`,
`docs/openapi.yaml`, тесты.

Ресурсы `templates` и `hr_templates` по §8. Режим `source` — только
администратор площадки, отдельной проверкой, а не колонкой матрицы.
